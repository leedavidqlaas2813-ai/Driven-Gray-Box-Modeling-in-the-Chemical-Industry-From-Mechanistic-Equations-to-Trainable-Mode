# 7. 从教学代码到准生产级工业灰箱系统

这一章把前面的 CSTR 灰箱模型升级为一套可审查的工程实现，代码在
仓库 `industrial_greybox/` 包中，设计说明见
[industrial_greybox/README.md](../../industrial_greybox/README.md)。

> **边界。** 本章所有数字来自合成数据。合成数据的噪声是独立同分布的正态
> 量，真实工厂还有偏差、漂移、串扰、量程压缩、通讯丢包和多速率采样。
> 本章演示的是**工程结构**，不是任何装置的验证结果。

## 7.1 五个工程问题

| 问题 | 教学代码 | 本章做法 |
|---|---|---|
| 刚性/突变工况发散 | 固定步长显式 Euler | 可微 RK4（默认 2 子步）、IMEX 线性隐式、Euler 对照 |
| 长周期滚动累积误差 | 无保护 | NaN/Inf 回退上一步、状态守护区间、诊断计数 |
| 化验死时间 | 状态同步 | 结果时刻减死时间；在线用时间戳缓冲回查 |
| 历史数据脏 | 不处理 | 硬边界、毛刺、变化率、死区、限长插值，全部留痕 |
| 参数缓慢漂移 | 固定 | 结垢/老化慢变修正，结构上单调不增 |

## 7.2 数值稳定性：为什么不是简单“换个积分器”

CSTR 的线性衰减项是 `1/τ`（浓度）和 `1/τ + UA`（温度）。显式格式的稳定
条件为 `h·a < 2`。用一个准刚性工况检验：

- `τ = 0.35 min` → `1/τ = 2.86 min⁻¹`
- `UA = 0.6 min⁻¹` → `a = 3.46 min⁻¹`
- `h = 1 min` → `h·a = 3.46 > 2`，显式 Euler **不稳定**

`numerics.explicit_stability_ratio()` 把这个比值直接算出来，用于在报表里
解释“为什么这条工况必须用 IMEX 或更小步长”。

IMEX 只对线性部分做隐式：

```
x_{n+1} = (x_n + h·(b + n(x_n))) / (1 + h·a)
```

对 CSTR 而言 `a = [1/τ, 1/τ + UA]`，因此短停留时间、强冷却都不再受
显式稳定域限制。反应项仍是显式，若 `h·k_eff` 很大（极快反应），仍需
减小 `dt`——这一点必须写进模型卡，不能靠“IMEX 稳定”一句话带过。

**数值守护的正确语义**：非有限值时回退到**上一步**，不是填 0。0 是有
物理意义的浓度；用 0 顶替 NaN 等于伪造标签，并且会静默污染后续梯度。

## 7.3 时滞：对齐方向反了会制造虚假残差

```
化验结果在 result_time 到达
它代表 process_time = result_time − dead_time 时刻的反应器状态
```

正确做法是把**目标**拉回过程时刻；错误做法是用**当前预测**去减迟到的
化验值。后者的残差里混入了 `dead_time` 分钟内的过程变化，表现为规律的
滞后偏差，模型会被训练去补偿这个假偏差，上线后死时间稍有变化就失效。

在线影子运行必须用时间戳缓冲（`delays.ShadowBuffer`）：

```python
buffer.push(time_min, predicted_state)
...
predicted_then = buffer.query(result_time - dead_time)
residual = lab_value - predicted_then
```

若 `query` 返回 `None`（历史已被缓冲区丢弃），必须记为 `stale_history`，
不能悄悄用当前值顶替。

## 7.4 数据清洗：标记不等于删除

四条原则：

1. 每条规则只**标记**原因，不静默修改；
2. **被规则删除的值绝不插值**——否则清洗白做；
3. 质量目标（化验）从不插值——伪造化验值就是伪造标签；
4. 死区/变化率默认只标记：真实稳态与真实阶跃都会触发，需要工程师复核。

规则顺序：`硬边界 → Hampel 毛刺 → 变化率 → 死区 → 限长插值`。
硬边界优先，避免极端毛刺把中位数/差分统计拉偏。

## 7.5 慢变参数：把物理先验写进结构

```
UA_eff  = UA_0 · exp(δ_ua),          δ_ua ≤ 0（主趋势）
k_eff   = k · exp(δ_rate + δ_activity), δ_activity ≤ 0（主趋势）
```

**初始化必须让训练起点就是机理模型。** 若输出层偏置取 0，
`sigmoid(0) = 0.5`，UA 一上来就比名义值低约 26%——等于用一个未经数据
支持的“装置已结垢一半”假设去拟合。本包把偏置设为 `-6`
（`sigmoid(-6) ≈ 0.0025`），并在单元测试中断言两条轨迹在物理精度内一致。

## 7.6 损失必须按通道归一化

工业标签的监督密度极不均衡：一个 4 h 窗口里温度有 41 个采样点全程可测，
浓度可能只有 6 个化验点。若把两个通道混在一起归一化，温度项会以约
`41 : 6` 的比例压倒浓度项——网络于是优先拟合温度，让质量软测量的主目标
变差。这不是网络容量不足，而是**损失写错了**。

本包的做法分两步：

1. **通道内归一化**：每个通道的损失 = 该通道加权平方误差 / 该通道权重和；
2. **通道间加权**：按 `ModelConfig.channel_weights`（默认 `[1.0, 0.25]`）
   合并，表达“浓度是主目标、温度是辅助约束”。

对应的约定：

- `WindowedDataset.weights` 只做 **0/1 掩码**（该点是否可监督）；
- 通道重要性只写在 `channel_weights` 里。不要用逐点权重表达，否则权重
  会同时编码“数据密度”和“工艺重要性”，无法解释。

消融实验（12 条运行、25 epoch、合成数据）对比了四种配置：

| 配置 | C_A RMSE (mol/L) | 偏差 (mol/L) |
|---|---|---|
| 机理基线（无修正） | 0.0104 | +0.0066 |
| 仅速率修正 | 0.0103 | +0.0063 |
| 仅慢变修正 | 0.0106 | +0.0069 |
| 两者全开 | **0.0098** | **+0.0056** |

注意：在修正通道归一化**之前**，“仅速率修正”反而比基线差（0.0172 vs
0.0114）。那正是温度项压倒浓度项的表现。这个反例说明：调网络之前，
先检查损失是否忠实表达了工程目标。

### 开环指标与影子指标可以不一致

同一批训练/测试运行，在两种评估下结论不同：

| 评估方式 | 灰箱 | 机理基线 |
|---|---|---|
| 开环窗口（20 min，从化验锚点滚动） | **0.0098** | 0.0104 |
| 影子运行（约 100 min 连续滚动，含状态重锚） | 0.0148 | **0.0110** |

> 表中两组数字来自同一组训练配置（12 条运行、25 epoch、`stride=4`）的
> 两次独立评估。换成 8 epoch、`stride=8` 时，影子指标变为 0.0150 vs
> 0.0114——结论（排序）不变，绝对值会随训练量变化。引用时请连同配置一起
> 记录，不要单独摘数字。

原因不是实现错误，而是**预测时长与状态更新方式不同**：

- 开环只在 20 min 内滚动，且每次从新的化验锚点出发，衡量的是“短期动态
  是否学对”；
- 影子运行连续滚动约 100 min，网络修正项（速率修正 + 慢变修正）在训练
  窗口外持续外推，任何小的速率偏差都会累积成浓度偏差。

这带来两条工程结论：

1. **选型必须用与实际部署一致的评估方式。** 软测量上线后是连续滚动的，
   因此影子指标才是决策依据；开环指标只用于诊断动态结构。
2. **修正网络的幅度限制是外推保护。** `max_log_correction`（默认 0.25）
   与 `max_decay_log`（默认 0.6）直接决定“最坏情况能偏离机理多少”。
   如果把它们放宽到能完美拟合训练数据，长周期外推会更容易漂移。

若影子指标持续劣于机理基线，正确的动作**不是**继续调网络，而是：
检查慢特征是否真的反映结垢/老化、确认训练窗口是否覆盖部署时长、
必要时缩短状态重锚间隔（提高化验频率）。

### 三项针对长期外推的改进

上一节留下的问题是"开环好、影子差"。针对它实现了三层机制，细节见
[industrial_greybox/README.md 第 6 节](../../industrial_greybox/README.md)：

1. **多步滚动一致性惩罚**：训练时从窗口中途**加扰动**后重新起算，向前
   展开若干步，要求回到原轨迹。它把"重锚造成的偏差应能被动力学吸回"
   写进损失，直接对应长周期滚动。

   > **两个必须记住的坑**：第一，若不加扰动，确定性积分器从精确状态
   > 重新起算必然精确复现原轨迹（半群性质自动成立），惩罚恒为 0。第二，
   > 即便加了扰动，原始惩罚量级约 5e-6，而数据损失约 0.07——权重取 0.1
   > 时只占 7e-6，仍然形同虚设。本包用**归一化**（除以轨迹自身动态幅度）
   > 解决后者，使权重可直接理解为"占主损失的比例"。
   >
   > 实测（12 条运行、8 epoch、`stride=8`）：关闭时影子灰箱 0.01458
   > 劣于机理 0.01142；开启（权重 0.1）后降到 **0.00962**，首次优于机理
   > 基线的 0.00976，且开环同步改善——不是靠牺牲短期精度换长期稳定。
2. **域外渐近门控**：修正网络在远离训练域时平滑关闭。**关键物理判断**是
   两类修正的域外行为不同——符号自由的速率修正与慢变残余项应回退到 0，
   而单调的结垢/老化主趋势**必须保持**（老装置本来就该结垢更多）。
3. **自适应重锚**：用稳健 MAD 尺度 + 连续确认区分"仪表坏值"与"真实漂移"，
   并用指数平滑替代瞬时跳变。两个实现细节值得记住：尺度必须有下限
   （否则恒定偏差会让 MAD 坍缩、修正永久停止）；确认计数必须与门控解耦
   （否则形成自锁，模型既不敢修正也认不出漂移）。

## 7.7 一个必须知道的 Keras 3 陷阱

**Keras 3 的 `Loss.__call__` 不会把 `sample_weight` 传给子类的 `call`。**
它先调用 `call(y_true, y_pred)`，再把权重交给 `reduce_weighted_values`
做整体缩放：

```python
# 错误：sample_weight 这里永远是 None
class MaskedLoss(keras.losses.Loss):
    def call(self, y_true, y_pred, sample_weight=None): ...
```

工业数据里“没有化验”和“浓度为 0”必须区分。若掩码失效、未监督点又被
填成 0，模型实际学到的是“出口浓度趋向 0”——这不仅是精度问题，在安全上
也很危险。

正确做法是重写 `Model.compute_loss`（它**能**拿到 `sample_weight`）：

```python
def compute_loss(self, x=None, y=None, y_pred=None, sample_weight=None, training=True):
    total = masked_squared_error(y, y_pred, sample_weight)
    for extra in self.losses:
        total = total + self._aggregate_additional_loss(extra)
    return total
```

单元测试固定了这一语义：未监督点的离谱误差不得影响损失值。

## 7.8 影子运行与报表

影子运行只使用当时已到达的信息，输出固定列的结构化日志：

```
campaign_time_min, run_id, time_min,
mechanistic_c_a, mechanistic_temperature_K,
greybox_c_a, greybox_temperature_K,
correction_c_a, correction_temperature_K,
online_c_a, lab_c_a, truth_c_a,
residual_vs_lab, residual_vs_truth,
in_domain, nonfinite_step, clipped_step, stale_history, config_signature
```

`mechanistic_*` 与 `greybox_*` 共用同一个积分实现（`use_corrections=False`
只关闭网络修正），因此 `correction_*` 纯粹反映模型修正，不混入数值格式
差异。

### 模型选型必须看“误差随时长”的分箱报表

影子运行从运行起点锚定状态、随后滚动上百分钟，而训练窗口可能只有
20–40 min。两者不是同一个问题：

- **开环 20 min**：衡量短期动态是否学对；
- **滚动 100 min**：衡量模型偏差是否累积。

同一对模型完全可以在这两个指标上**排名相反**。本包用
`reports.metrics_by_horizon`（报表中的“按预测时长分箱”）把这件事显式
暴露出来，而不是用单个总 RMSE 掩盖。

### 参数可辨识性：条件数还不够

`diagnostics.parameter_identifiability` 给出灵敏度矩阵的**条件数**，
但两个参数的可辨识性本质上是**子空间**问题：A 与 B 共线，不代表 A 与 C
也共线。三个参数可以两两不共线却只有两个独立方向。

因此用 `sensitivity_correlation_matrix` 输出完整的相关矩阵（按列尺度
归一化后求 Pearson 相关）。|r| > 0.95 表示两者几乎无法从当前数据分别
辨识，此时应补充能打破共线的工况——例如只改变冷却而不改变进料——
而不是继续扩大网络。

### 状态重锚（soft-sensor update）

工业软测量的通行做法是：每次化验结果到达时更新状态。但实现方式很容易
写错。拿到的化验值对应的是 `process_time`，而当前状态已经推进到
`time_min`，中间隔着整个死时间。因此**不能**把 `lab_value` 直接赋给当前
状态；正确做法是把“过程时刻的模型误差”当作缓慢变化的加性偏差：

```text
bias = clip(lab − ŷ(process_time), ±max_bias_correction_mol_l)
C_A(t_now) ← C_A(t_now) + bias
```

偏差必须**有界**：若某次化验与模型差距远超限值，说明工况外推、仪表故障
或死时间估计错误，此时强行重锚只会掩盖问题。日志中记录
`applied_bias_mol_l` 与 `bias_clipped`，供复核。

报表按日、按运行、按域内/域外、按预测时长分别给出 RMSE、MAE、偏差与
P90 绝对误差，并附有效样本数。

## 7.9 讨论与练习

1. 把 `IntegratorConfig.method` 从 `rk4` 改成 `euler`，在准刚性工况
   （`τ = 0.35 min`）下观察温度轨迹。用 `explicit_stability_ratio` 解释
   你看到的现象。
2. 把 `DelayConfig.analysis_delay_min` 从 12 改成 0，但化验时间戳仍按
   “结果到达”解释。残差图会出现什么结构？为什么这不是模型误差？
3. 关闭 `HygieneConfig` 中的毛刺规则，看灰箱模型在测试集上的误差如何
   变化。误差变大是否说明毛刺规则“有用”？还是说明模型在拟合坏值？
4. 把 `SlowDriftConfig.initial_decay_bias` 从 -6 改成 0，重新训练。
   观察开环误差的偏差项（bias）。解释为什么初始偏置会改变系统偏差。
5. 尝试用 `Loss.call` 写逐点掩码，验证它**不生效**；再改用
   `compute_loss`。用一句话总结 Keras 3 的这个行为对工业标签设计的影响。

> **部署前的最后一道关**：本包的所有阈值（`HygieneConfig`、`DelayConfig`、
> `PhysicsConfig`）都来自教学假设。接入现场前，必须由工艺、仪表和安全
> 人员逐项审核，并用独立批次/时间段留出的数据验证。数据驱动模型不能
> 绕过现有联锁、操作规程或独立安全审查。

## 7.10 把工程规则换成具体数字

以本章的准刚性例子为例，\(\tau=0.35\) min、\(UA=0.6\ \mathrm{min^{-1}}\) 时，
温度衰减速率尺度为 \(a=1/\tau+UA=1/0.35+0.6\approx3.46\ \mathrm{min^{-1}}\)。
若步长 \(h=1\) min，显式稳定比 \(h a=3.46\)，大于近似上限 2；若把步长减到
0.25 min，比值降到 \(0.865\)。这是“为什么步长会影响稳定性”的计算，不代表
0.25 min 对所有真实设备都足够，仍须做收敛检查。

死时间例子中，若化验在第 35 min 到达、总死时间为 12 min，它对应的过程时刻是
\(35-12=23\) min。假设模型在 23 min 预测 \(0.80\ \mathrm{mol/L}\)，化验值是
\(0.84\ \mathrm{mol/L}\)，过程时刻残差为 \(+0.04\ \mathrm{mol/L}\)。如果错误地拿
35 min 的当前预测（例如 \(0.90\ \mathrm{mol/L}\)）比较，就会算出
\(-0.06\ \mathrm{mol/L}\)，甚至把误差方向也反过来。缓冲区按时间戳查询的目的，
就是确保比较的是“同一过程时刻”。

同理，若一个窗口有 41 个有效温度点、只有 6 个有效化验浓度点，直接把所有点
混在一起平均会让温度监督约占 \(41/(41+6)\approx87\%\)。按通道先分别除以各自
有效权重和，才能让“浓度是主目标、温度是辅助约束”由显式通道权重表达，而不是
由采样频率意外决定。
